Privacy Policy

This policy explains what the PayPulse sandbox stores, why it stores it, and which third parties process data during a demonstration.

Last updated: November 11, 2026

Sandbox only The demo uses synthetic customer records and PayPal Sandbox credentials. Do not enter real payment card data, passwords, government identifiers, or sensitive personal information.

1. Data collected

The demo can store the following operational records:

  • Invoice numbers, customer names, line items, amounts, and payment status.
  • Subscription plan names, billing dates, and account identifiers.
  • Dispute events, evidence status, and refund status.
  • Webhook event type, simulated latency, response status, and log summaries.
  • Agent prompts, generated recommendations, and action outcomes.

2. How data is used

Data is used to demonstrate receivables reporting, invoice actions, collection nudges, subscription views, dispute defense, webhook handling, and agent-assisted operations. The demo does not sell data or use it for advertising.

3. Third parties

PayPal processes sandbox account, invoice, order, subscription, and dispute data under its own terms. If a model provider is configured, prompts and relevant operational context may be sent to that provider. No third-party analytics or advertising scripts are included in the dashboard.

4. Retention

Demo state is held in server memory and is cleared when the server restarts or when the demo reset action runs. Logs may persist for the lifetime of the running process. Do not use the demo as a system of record.

5. Security

PayPal and model credentials stay on the server in environment variables. Browser responses include security headers, and direct API access can require an API key. A public deployment still needs authentication, restricted origins, monitoring, and a real webhook configuration.

6. Your choices

You can reset the demo to clear its in-memory operational state. Because this is a sandbox, do not submit data you would not be comfortable losing on a restart. For a self-hosted deployment, the operator controls retention and access.

7. Contact

For privacy questions about this demo, contact the project maintainer through the repository or delivery channel that provided it.
